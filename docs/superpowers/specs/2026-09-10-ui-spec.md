# UI Spec — Portfolio (S1, S2, S3, S5)

- Date: 2026-09-10 · Task 2 of `docs/superpowers/plans/2026-09-10-portfolio-overhaul.md`
- Scope: portfolio pages, header, footer, primitives. S4 (storybook, audio dock) lives in `2026-09-10-ui-spec-storybook.md`.
- Authority: spec §2 decisions > this file for visuals > UX brief for copy/order. Tailwind 3.4.14 core utilities only, no plugins, icons from `lucide-react` 0.475 (`Menu`, `X`, `MapPin`, `Mail`, `Linkedin`, `Github`, `ArrowRight`, `ArrowLeft`, `ArrowUpRight`, `Copy`, `Check`).

### Contrast (WCAG 2.x relative luminance)

Command (script at `<scratchpad>/contrast.mjs`: sRGB channel `c <= 0.03928 ? c/12.92 : ((c+0.055)/1.055)^2.4`, `L = 0.2126R + 0.7152G + 0.0722B`, ratio `(L1+0.05)/(L2+0.05)`):

```

```

`line` fails 3:1 by design (a 3:1 gray on every card and divider is heavy). It is allowed only where the boundary is not needed to identify a control: cards are identified by their heading text, dividers carry no meaning. Every control whose shape matters uses `line.strong`, `ink` or `accent`.

### `tailwind.config.js` objects (paste exactly)

`theme.container` (not inside `extend`):

```js
container: {
  center: true,
  padding: "clamp(1rem, 4vw, 1.5rem)",
  screens: { "2xl": "72rem" },
},
```

Compiled with the 3.4.14 CLI, this yields `.container { width: 100%; margin-left/right: auto; padding-left/right: clamp(1rem, 4vw, 1.5rem) }` and `@media (min-width: 72rem) { .container { max-width: 72rem } }`. Fluid below 72rem, capped at 72rem (padding included, same as `max-w-6xl px-4 sm:px-6`). Why not `padding: { DEFAULT, sm }`: the container plugin only emits padding at `container.screens` min-widths and sets `max-width` to that same width, so an `sm` key would cap the page at 640px until the next screen. `clamp` gives 16px at 390px and 24px from 600px up with a single media query.

`theme.extend.colors` (portfolio part; Task 4 merges the S4 `book` object next to it):

```js
muted: "#57534E",
accent: { DEFAULT: "#0F766E", hover: "#115E59", soft: "#F0FDFA" },
```

## S3 Portfolio components

Conventions: icons are `aria-hidden="true"`, sized `size-4` inline with text or `size-5` in icon buttons. Every external link has `target="_blank" rel="noopener noreferrer"` and ends with `<span className="sr-only"> (opens in new tab)</span>`. Hover/focus transitions come only from the strings below (see S5). No element gets `outline-none` or `focus:ring-*`: the global `:focus-visible` rule in S5 is the only focus style.

```jsx
      {open ? <X className="size-5" /> : <Menu className="size-5" />}
    </button>
  </div>
  <nav id="mobile-nav" aria-label="Main" hidden={!open} className="border-t border-line md:hidden">

```

```js
desktopLink: "relative inline-flex min-h-10 items-center rounded-md px-3 text-sm font-medium text-muted transition-colors duration-150 hover:text-ink aria-[current=page]:text-ink after:absolute after:inset-x-3 after:-bottom-3 after:h-0.5 after:rounded-full aria-[current=page]:after:bg-accent forced-colors:after:forced-color-adjust-none forced-colors:aria-[current=page]:after:bg-[color:Highlight]",
menuButton:  "inline-flex size-11 items-center justify-center rounded-lg border border-line-strong text-ink transition-colors duration-150 hover:border-ink md:hidden",
mobileLink:  "flex min-h-11 items-center border-l-2 border-transparent px-3 text-base font-medium text-muted transition-colors duration-150 hover:text-ink aria-[current=page]:border-accent aria-[current=page]:text-ink",
```

- Active item: `ink` text plus a 2px `accent` bar (desktop: under the item, on the header's bottom edge; mobile: left edge). The bar is the non-color cue; ink vs muted alone is not relied on. In forced colors the desktop bar opts out of color adjustment and paints `Highlight`, so it stays visible.
- Mobile links close the panel on click (the pathname effect alone misses same-page taps).
- menuButton boundary is `line.strong` (3.70:1 on the surface header), never `line`.
- At viewport heights of 30rem or less (e.g. 1280×720 at 400% zoom = 320×180 CSS px) the header is `static`, so it does not cover the short viewport (WCAG 1.4.10, 2.4.11). S5 drops `scroll-padding-top` at the same height.
- The mobile `<nav>` must carry no display utility (`flex`, `block`): Preflight hides `[hidden]` with class-level specificity, and a later display utility would override it. `flex` goes on the inner `<ul>`.
- Header is `z-30`; the audio dock (S4) is `z-40`; the skip link is `z-50`.

Bottom padding budget: the dock sits at `bottom-4` (1rem) and S4 keeps it at most 78 px tall, so it covers at most 94 px (plus `env(safe-area-inset-bottom)`) of the viewport bottom. `7rem + env(safe-area-inset-bottom)` (112 px) of footer padding means that when the page is scrolled to the end, the footer row sits at least 1rem above the dock on every width. If S4's dock grows past 78 px, raise `7rem` to dock height + 2rem.


- Forced colors (Windows High Contrast): the pressed chip opts out of color adjustment and uses `Highlight` fill and border with `HighlightText` label and count, so the selected filter stays visible. The `forced-colors` variant and `forced-color-adjust-*` utilities ship in the installed Tailwind 3.4.14.

- One string for both states: the `aria-pressed:` variants style the pressed chip, so no conditional class logic. Pressed = accent fill with white text (5.47:1) and count in `accent.soft` (5.25:1); default = white chip with `line.strong` outline (3.54:1 on canvas). Fill vs outline is the non-color state cue.
- A pressed chip does not change on hover (pressing it again does nothing).
- Focus: global S5 outline (accent, 2px, offset 2px) on every chip, pressed or not.
- Chips wrap at 390px (`flex-wrap`); never `overflow-x-auto`.

## S5 Motion & focus

### `app/globals.css`

Keep the plan's Task 4 file and extend only the `html` rule in `@layer base`:

```css
html {
  scroll-behavior: smooth;
  scroll-padding-bottom: 7rem; /* fixed audio dock (94 px incl. offset): focused elements near the bottom are scrolled clear of it */
}
@media (min-height: 30rem) {
  html { scroll-padding-top: 5rem; } /* sticky header (h-16) + 1rem; short viewports get none because the header is static there (S3) */
}
```

The rest stays as in the plan:

- Focus ring: `:focus-visible { outline: 2px solid theme("colors.accent.DEFAULT"); outline-offset: 2px; }`. Accent is 5.24:1 on canvas and 5.47:1 on surface; the 2px offset shows page color between a primary button's fill and its ring. Outlines follow `border-radius` (rounded-lg, rounded-full chips).
- Reduced motion: the `@media (prefers-reduced-motion: reduce)` block (`scroll-behavior: auto`, animation and transition durations `0.01ms`).

### Rules

- Transitions: only `transition-colors duration-150` (text, borders, fills) and `transition duration-150` (cards: border color + `shadow-sm`). Nothing above 150ms on portfolio pages; 200ms is the hard ceiling.
- No transforms on hover (no lift, scale or arrow nudge), no `animate-*`, no scroll-triggered effects, no intro animation. With nothing moving, the global reduced-motion block is the only reduced-motion handling needed; no `motion-reduce:` utilities.
- Never `outline-none`, `focus:outline-none` or `focus:ring-*` on portfolio elements. The global rule is the single focus style, so every link, button, chip and card shows the same ring.
- Skip link becomes visible on focus (S3 layout string) and moves focus target to `#main`.
- Mobile menu: on Escape, return focus to the Menu button (UX brief §6). The header needs a `ref` on the button and `buttonRef.current?.focus()` in the Escape handler. Closing by link click or route change leaves focus where the browser puts it.
- Sticky header uses a solid `bg-surface`; no `backdrop-blur`, no translucency.

## Deviations from spec §4

1. Added `line.strong` `#8A847E` (nested as `line: { DEFAULT, strong }`, so `border-line` is unchanged). `line` `#E7E5E4` is 1.20:1 on canvas and cannot mark control boundaries at 3:1.
2. Sticky header is solid `bg-surface` + `border-b border-line`, not `white/85` + backdrop blur. The brief for this pass bans glassmorphism, and solid also keeps text scrolling underneath from showing through.
3. Container padding is `clamp(1rem, 4vw, 1.5rem)`, not `px-4 sm:px-6`. With Tailwind's container plugin, per-screen padding also sets a per-screen max-width, which would cap the page at 640px on tablets.
4. Card hover is a darker border plus `shadow-sm` with no lift, meeting "subtle hover" without motion.
5. Project detail order follows the UX brief (Overview last), which the brief records as a refinement of spec §3.
